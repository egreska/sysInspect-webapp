# Loaded SiteRacking coerces Standardized to Mixed when several specs name a manufacturer

A stored SiteRacking section can say Standardized while more than one spec names a manufacturer, because decode used to trust `mode`. It can also contain specs with no manufacturer name. The editor cannot save either state: saves omit nameless specs, and Standardized is refused once two specs name a manufacturer. On load, and when a section is created, nameless specs are dropped, then a Standardized section that still has more than one named spec becomes Mixed. Callers then see a profile the editor could have saved. Leaving the stored mode in place would make every caller handle an illegal Standardized. Keeping nameless specs until the next save would make a loaded profile differ from a saved one. Rejecting the whole JSON blob would drop Site Information and Load Information with it.

**Considered options:** trust stored mode and keep nameless specs; drop nameless specs and coerce that section to Mixed (chosen); fail the blob and yield an empty profile.

**Consequences:** Do not trust Standardized when more than one spec names a manufacturer. Do not keep nameless specs on load or on creation. Do not fail the whole profile. A spec with no manufacturer name is not a recorded spec. Spec count changes only through the section: append while Mixed, drop nameless specs when becoming Standardized, or one blank seed when the section is empty. Field edits on an existing spec do not change the count. While editing, Mixed may still hold a blank spec. This pass does not add SiteRacking to Report or the web customer codec (ADR-0010).
